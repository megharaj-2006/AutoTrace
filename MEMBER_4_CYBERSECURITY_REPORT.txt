4.1 Security Actuator Daemon (services/actuator-security/ — Port 8081)
--------------------------------------------------------------------------------
- Framework: Python 3.11+ / FastAPI / Uvicorn.
- Port: 8081 (frozen project assignment).
- Core Modules:
  * src/app.py:
    FastAPI service with lifespan management, dependency injection, and endpoints:
    - POST /api/v1/quarantine: Disconnects compromised container from autotrace-mesh.
    - POST /api/v1/release: Authenticated recovery endpoint to reconnect container.
    - GET /health: Liveness probe returning service status and Docker availability.
    - GET /ready: Readiness probe (fails 503 if live mode without Docker).
    - GET /api/v1/quarantine/status: Query active quarantined containers.
  * src/containment.py:
    Core ContainmentEngine using official Python Docker SDK (docker.from_env()):
    - Zero subprocess shell execution, preventing command injection.
    - 5-step containment sequence: duplicate check -> container existence check ->
      network membership verification -> forced disconnect -> post-disconnection verification.
    - Real-time performance timing (perf_counter_ns) evaluating <2000ms latency target.
    - Thread-safe state tracking for idempotent quarantine calls.
    - Safe Dry-Run mode enabled by default for offline developer workstation safety.
  * src/models.py:
    Pydantic schemas with strict validation:
    - Regex pattern ^[a-zA-Z0-9][a-zA-Z0-9._-]{0,127}$ on all container/service names.
    - Automatic alias support (culprit/culprit_service, target/target_service).
    - Auto-population of container_id from culprit_service if omitted.
    - Typed outcome enums: CONTAINED, FAILED, DRY_RUN, ALREADY_CONTAINED, RELEASED.
  * src/config.py:
    Environment-driven configuration with safe defaults:
    - ACTUATOR_ALLOWED_CULPRITS: reviews-service, order-service, gateway-service
    - ACTUATOR_ALLOWED_TARGETS: payment-vault, order-service, gateway-service
    - ACTUATOR_PROTECTED_SERVICES: redpanda, redis, telemetry-collector, graph-engine,
      ml-detector, actuator-security, web-dashboard (hard block with HTTP 403)
    - ACTUATOR_CONTAINMENT_TARGET_MS: 2000ms
  * src/main.py: Entry point starting Uvicorn server on configured port.
  * Dockerfile: python:3.11-slim container image with curl and iptables.
  * pytest.ini: Pytest configuration with strict asyncio mode and fixture scopes.
  * requirements.txt: Clean dependencies (fastapi, uvicorn, pydantic, docker, httpx, pytest).

4.2 Network Containment Policies & PKI Hooks
--------------------------------------------------------------------------------
- Mechanism A (Docker Network Disconnect):
  Implemented in src/containment.py via Docker SDK.
- Mechanism B (Linux In-Container iptables):
  policies/iptables_isolate.sh: Injects `iptables -I OUTPUT -d <target> -j DROP`
  inside container namespace. Includes `./iptables_isolate.sh restore` routine.
- Mechanism C (Kernel eBPF Socket Drop):
  policies/socket_drop.bpf.c: eBPF cgroup_skb/egress hook dropping TCP packets
  destined for protected port 5003 (payment-vault).
- Zero-Trust PKI Identity Revocation:
  pki/spiffe_revocation.py: SPIFFE/SPIRE workload identity revocation hook
  invalidating SVIDs (spiffe://autotrace.local/ns/default/sa/<service>) upon quarantine.

4.3 Lateral-Movement Exploit Demonstration (testbed/attacks/)
--------------------------------------------------------------------------------
- File: testbed/attacks/trigger_lateral_exploit.sh
- Scenario: Simulated compromised reviews-service (5002) calls payment-vault:5003/process.
- Automated 4-Step Verification Workflow:
  Step 1: Pre-flight check verifying reviews-service (5002), payment-vault (5003),
          and actuator (8081) are reachable.
  Step 2: Baseline exploit request to POST /exploit/lateral. Confirms HTTP 200.
  Step 3: Dispatches authenticated quarantine request to Actuator (8081).
  Step 4: Retries exploit request. Confirms connection is blocked (HTTP 502/504/timeout).
- Verdict Output:
  * [✓] DEMONSTRATION PASSED (Exit 0): Unauthorized traversal succeeded before, blocked after.
  * [!] DEMONSTRATION FAILED (Exit 1): Target still reachable after quarantine.
  * [INCONCLUSIVE] (Exit 2): Prerequisites offline or baseline failed before quarantine.

4.4 Chaos-Testing Scripts (testbed/chaos/)
--------------------------------------------------------------------------------
- testbed/chaos/inject_latency.sh:
  Injects bounded compute delay (1-10000ms) down the gateway -> order -> payment-vault chain.
- testbed/chaos/inject_packet_drop.sh:

- testbed/chaos/simulate_downstream_failure.sh:

  * ONLY Docker virtual bridge network detachment and reattachment were verified.
  * Application-level traffic blocking (e.g., HTTP payload drops or socket drops) was
    NOT tested in this verification.
- Defense-in-Depth & Odysseus Isolation:
  * All four existing Odysseus containers (`odysseus-odysseus-1`, `odysseus-searxng-1`,
    `odysseus-chromadb-1`, `odysseus-ntfy-1`) and `odysseus_default` remained completely
    isolated and untouched throughout all tests.
- Remaining Policy & Integration Limitations:
  * Mechanism B (in-container iptables): Standalone script; requires `CAP_NET_ADMIN` in container;
    not invoked by the actuator daemon.
  * Mechanism C (eBPF socket drop): Standalone C source for `cgroup_skb/egress`; requires userspace
    loader (BCC/libbpf) and Linux kernel with BTF; unverified against live traffic.
  * Zero-Trust PKI (SPIFFE/SPIRE): Operates in simulated audit mode (`REVOKED_SIMULATED`);
    live gRPC integration requires production SPIRE Server deployment.
